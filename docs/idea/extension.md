# Extension (Manifest V3)

Chrome MV3. Three execution worlds, strict separation. Built with [WXT](https://wxt.dev/) (or CRXJS) + Bun + TypeScript; UI is a prebuilt SolidJS bundle.

## Layout

```
src/
├── entrypoints/           # MV3 manifest is generated by WXT from wxt.config.ts (repo root)
│   ├── background.ts      # service worker — agent loop, provider, MCP, changeset
│   ├── content.ts         # content script (isolated) — DOM, overlay, picker, recorder
│   ├── injected.content.ts # MAIN-world bridge — page facts + chart libs (read-only)
│   └── sidepanel/         # SolidJS app — chat + MCP management + history + settings
│       ├── index.html
│       └── App.tsx
├── agent/                 # Vercel AI SDK loop, tool defs, prompts  → agent.md
├── dom/                   # mutation primitives, selector engine    → live-edit.md
├── changeset/             # store, Markdown report renderer          → handoff.md
├── mcp/                   # MCP client manager, auth                → mcp.md
└── shared/                # Zod schemas, message types (panel ↔ sw ↔ content)
```

## Manifest essentials

| Key | Value | Why |
|-----|-------|-----|
| `manifest_version` | 3 | Required. |
| `side_panel.default_path` | Source config: `sidepanel/index.html`; emitted value: read `build/chrome-mv3/manifest.json` | Persistent UI, survives page nav. Source and emitted paths are distinct; see verification below. |
| `background.service_worker` | `background.ts` (module) | Agent loop + key custody. |
| `content_scripts` | match `<all_urls>`, `run_at: document_idle` | DOM access on the active tab. |
| `permissions` | `sidePanel`, `storage`, `activeTab`, `tabs`, `identity`, `webNavigation`, `debugger`, `scripting` | `identity` = MCP OAuth PKCE; `debugger` = device emulation; `webNavigation` = frame enumeration; `scripting` = SW-only reinjection of manifest-declared shipped files into accessible existing HTTP(S) tabs on install/update and worker boot. No remote code or additional host grant. |
| `host_permissions` | `https://openrouter.ai/*`, `https://glitchtip.infra.developerz.ai/*` (static) | The SW calls the BYOK model endpoint + crash reporting directly; page hosts stay opt-in. |
| `optional_host_permissions` | `<all_urls>` | User grants page access when they want it everywhere. |

### Side-panel build verification

| Layer | Path / evidence |
|-------|-----------------|
| Source HTML entrypoint | `src/entrypoints/sidepanel/index.html` |
| Source config (`wxt.config.ts`) | `side_panel.default_path: 'sidepanel/index.html'` |
| Emitted Chrome manifest | `build/chrome-mv3/manifest.json` — generated by WXT, not the source config |
| Emitted target / existence | Pending fresh-build verification; no Chrome build artifacts were present during this edit. Do not treat either source path or `sidepanel.html` as verified output. |

Verification command: `DZ_TEST_WORKERS=2 DZ_E2E_WORKERS=2 bun run gate` (build + loaded-extension E2E included). The mount test in `test/e2e/smoke.spec.ts` reads the emitted manifest, reports `Emitted side_panel.default_path: <value> (target exists)` and a matching test annotation, requires a nonempty path to an existing file within `build/chrome-mv3`, then opens that exact entry through `openExtensionPage` and asserts `.dz-app` mounts. Missing artifacts fail, never skip. Record the reported value and target-existence result after the fresh gate; source inspection alone is not build evidence.

## Messaging

Typed message bus over `chrome.runtime` / `chrome.tabs.sendMessage`. All payloads Zod-validated in `shared/`.

```
panel  ──UserMessage──►  sw   (start agent turn)
sw     ──DomTool──────►  content  (query / mutate / capture)
content──ToolResult───►  sw
sw     ──Stream───────►  panel    (tokens, tool calls, changeset updates)
sw     ──McpTask──────►  backend  (handoff)
```

## CSP / MV3 constraints

- **No remote code, no `eval`.** Solid is prebuilt to static JS — that's why we prebuild with Bun.
- **Service worker is ephemeral.** It can be killed; persist in-flight state to `chrome.storage.session`, resume on wake.
- **OpenRouter calls from the service worker only.** Content scripts run in the page's world — never put the key there.

## Why side panel (not popup / injected panel)

- Survives navigation and reloads — the design conversation outlives the page.
- Its own origin + CSP — safe place to run the Solid UI and hold no page trust.
- Doesn't fight the page's own z-index/styles the way an injected panel does.
